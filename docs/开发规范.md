# 开发规范（Python 版，业务开发唯一约定源）

> **适用**：在本框架（`BaseAdminCore.Python`）上新增业务。
> **本件是业务侧约定源**：`docs/框架索引.md`／`docs/框架使用指南.md` 中的「约定 #N」均指本件对应条。
> **关系**：框架能力只在框架面（`src/core`、`src/web`）演进；业务只写 `src/business` 与薄控制器（约定 1、7）。

## 0. 三条边界（谁维护什么）

| 面 | 谁维护 | 业务动作 |
|---|---|---|
| `src/core/`（实体基类、db、仓储、鉴权、权限、缓存、审计、中间件、服务原语） | 框架 | **只读**。缺能力/有缺陷 ⇒ 在框架面修复，业务侧不私改 |
| `src/web/`（应用工厂、中间件、API 路由） | 框架 + 业务 | 可加**薄**业务路由（绑定 → Service → `success`）；不改应用工厂/中间件结构 |
| `src/business/`、业务前端页、菜单种子 | 业务 | ★ **业务唯一落点** |

## 约定 1–14

### 约定 1｜业务代码只写 `src/business/`
业务实体、服务、DTO、业务种子放 `src/business/`（结构见约定 6）；控制器只做薄路由，业务逻辑不写进控制器；不把业务代码塞进 `core`／`web`。

### 约定 2｜编码：UTF-8 无 BOM ＋ LF
- `.py`／`.md`／`.toml`：UTF-8 **无 BOM**；`.json`：UTF-8 无 BOM；
- 行尾一律 **LF**；
- 4 空格缩进；类 `PascalCase`，模块/函数 `snake_case`，接口/抽象 `I` 前缀（Python 用 `Protocol`/抽象基类）。

### 约定 3｜异步规范
- 全链路 `async`/`await`；I/O 用异步 API（`asyncpg`、`redis.asyncio`、`httpx.AsyncClient`）；
- **禁止同步阻塞**：`.result()`、`.wait()`、`run_until_complete` 嵌套、同步 ORM 调用；
- 不丢弃可等待对象；后台任务经 `JobScheduler`/事件总线，异常显式处理。

### 约定 4｜实体与种子
- 实体继承 `EntityTenant`（租户+审计+软删）或 `EntityTenantBaseData`（加机构数据权限），表名显式小写；
- 种子继承 `Seed` 并 `@register`，`order` 决定执行序，**幂等**（缺行插入、已有跳过）；
- **新增列必须可空或带 `server_default`/`default`**，否则存量库建列失败。

### 约定 5｜凭据与敏感信息
- 密钥/口令/连接串**不进仓**：走环境变量（`.env` 仅本地占位）；
- 日志与异常**不回显**敏感值（连接串密码、密钥、口令明文）；
- 初始管理员密码首登即改；测试探针账号带可识别前缀并自清理。

### 约定 6｜目录与命名
- 业务目录：`src/business/entities/`、`src/business/services/<域>/`、`src/business/dtos/`、`src/business/seeds/`；
- **单文件单类**；表名显式小写（`__tablename__ = "biz_xxx"`），列名 `PascalCase`（与框架库结构一致）。

### 约定 7｜框架面只读
- `src/core`／`src/web` 的框架机制只在框架面演进；业务发现缺陷在框架面修复，不在业务层长期私改；
- 业务确需框架级能力 ⇒ 在框架面按框架口径实现（同批更新文档）。

### 约定 8｜最小必要改动
只做与当前目标直接相关的改动；不顺手重构、不顺手格式化无关文件。存量不合规只登记，不在功能批里顺手改。

### 约定 9｜增量更新（禁止整对象覆盖）
更新只写明确允许的字段：DTO → 实体**逐字段判空/判改动**，禁止「读出整对象、改一处、整行覆盖」；审计列（`IsOnlyIgnoreUpdate` 语义）不被更新覆盖。

### 约定 10｜异常与错误码
- 规则不满足：`AppException(err_code, msg)`；参数问题：`BadRequestException`；出口统一 `success/fail`（HTTP 恒 200 + 业务码）；
- **新增错误码三步**：`ErrorKeys` 常量 ＋ `src/core/localization/Lang.zh-CN.json`／`Lang.en.json` 同键 ＋ 默认文案同步；
- 不无说明吞异常；对外信息稳定、可检索、**不泄露堆栈**；前端按 `errCode` 覆盖文案。

### 约定 11｜复用优先
先用框架既有原语：`Repository`、`ICacheService`、`PageInput`/`PageResult`（分页上界由 `PageInput` 夹到 200）、审计/软删、租户/数据权限过滤器、`PermissionMiddleware` 权限链、事件总线、`JobScheduler`、导入导出、代码生成预览、本地化。**不发明平行实现**。

### 约定 12｜验证要求（门前置）
改动后必须做**最小但有效**验证：
- 后端静态：`uv run ruff check src tests`（0 问题）；
- 后端测试：`uv run pytest tests`（受影响范围必须跑；真实 PG/Redis 未具备时说明未覆盖项）；
- 前端：`cd web && pnpm typecheck && pnpm build`；
- 无验证必须在提交说明**显式说明**。

### 约定 13｜文档与索引同批维护
结构性变更（新增/重命名/移动、新机制、新缓存键/Claim/配置键）与代码**同批**更新 `docs/框架索引.md`；用法变化同批更新 `docs/框架使用指南.md`。

### 约定 14｜全栈闭环（用户可见端点同批交付）
新增/变更**用户可见** API 端点时，同批完成：
1. 前端 API 模块 + 页面（`web/` 既有视图约定）；
2. **菜单种子**：目录/菜单/按钮权限键与路由一一对应（权限键 = 路由去掉 `/api/`，如 `bizOrder/page`）；
3. 后端 `ruff`＋`pytest` ＋ 前端 `typecheck`/`build` 全绿。
豁免仅限：纯机制型变更、内部端点（`/health`、`/ws` 等）、明确约定"先做后端"——**豁免须留痕**。

## 业务起步（五步）

1. **实体**：`src/business/entities/`，继承 `EntityTenant`/`EntityTenantBaseData`，显式 `__tablename__`。
2. **服务**：`src/business/services/<域>/`，注入 `AsyncSession`，用 `Repository`；构造函数签名便于 FastAPI 依赖注入。
3. **DTO**：Pydantic 模型就近 `dtos/`；更新 DTO 字段全可空（部分更新 `null=不改`）。
4. **薄控制器**：`src/web/api/<域>.py`，`UserDep` 取用户，`success(...)` 返回，在 `router.py` include。
5. **权限与菜单**：按钮权限键写入菜单种子（Type=3，`permission`）；前端加 API/页面。

## 提交前自检（10 条）

1. 只改业务面（`src/business`／薄控制器／前端页／菜单种子），框架面零改动；
2. 新端点齐：权限键、菜单/按钮种子、前端 API 与页面（或已留痕豁免）；
3. 新实体继承正确基类；新增列可空/有默认；新种子 `@register` 且幂等；
4. 新错误码三步齐（`ErrorKeys`／双语文案／默认文案）；
5. 更新逐字段（未整对象覆盖）；
6. 复用了既有原语（未造平行实现）；
7. 无密钥/口令入仓；日志与异常无敏感回显；
8. 编码 UTF-8 无 BOM + LF；
9. 门全绿（约定 12）；
10. 文档按约定 13 同批更新（如涉及结构或用法变化）。
